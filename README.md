# Проверка сделок Битрикс24

Скрипт открывает отчёт в Битрикс24, заходит в каждую сделку и пишет, что в ней поправить.

В Битриксе он **только читает**. Сделки, комментарии, задачи и поля он не меняет.

Результат: Excel-файл `results\check_latest.xlsx` (лист **«Нужно исправить»** — что поправить в сделках). В конце проверки файл обычно открывается сам.

---

## Для коллег (установщик Windows)

1. Скачайте и запустите **`Установить.exe`** (или `Установить.bat` из репозитория).  
2. В окне отметьте галочки:
   - скачать Node.js (если его ещё нет),
   - ярлык на рабочем столе,
   - ярлык в меню Пуск.  
3. Нажмите **Установить** — программа скачается с GitHub в `%LOCALAPPDATA%\Bitrix24-Deal-Checker`.  
4. Откройте ярлык **«Проверка сделок Битрикс24»** — откроется мини-приложение (не терминал).  
5. Вставьте ссылку на отчёт в поле → **Запустить** → залогиньтесь в Chrome → дождитесь конца.  
6. Кнопка **«Проверить обновления»** подтянет новый код с GitHub, не открывая терминал.

Сборка установщика и GUI у разработчика: `npm run build:exe`.

---

## Быстрый запуск из папки проекта

1. Один раз установите Node.js LTS: https://nodejs.org  
2. В папке проекта дважды кликните **`Проверка сделок.exe`**  
   (если exe нет — `npm run build:gui` или `Проверка сделок.bat`)  
3. Вставьте ссылку на отчёт → залогиньтесь в Chrome → дождитесь конца  
4. Откроется Excel с отчётом

---

## Что понадобится

- Windows 10 или 11
- Интернет (на первом запуске скрипт сам скачает нужные программы)
- Google Chrome — обычный браузер. Скрипт откроет **своё** окно Chrome, ваш обычный Chrome можно не закрывать
- Node.js — программа, которая запускает скрипт. Ставится один раз, см. ниже

Папка проекта — та, где лежат файлы `start.js` и `config.js`.

## 1. Установить Node.js (один раз)

1. Откройте сайт https://nodejs.org
2. Скачайте версию с кнопкой **LTS** (не Current). Нужна версия 18 или новее.
3. Запустите скачанный установщик.
4. Нажимайте **Next**, пока установка не закончится. Галочку **Add to PATH** не снимайте — она стоит по умолчанию.
5. В конце нажмите **Finish**.
6. **Закройте** все уже открытые окна PowerShell и «Командной строки». Иначе Windows ещё не увидит Node.js.

Проверка:

1. Нажмите клавишу Windows, наберите `powershell`, откройте **Windows PowerShell**.
2. Введите и нажмите Enter:

```powershell
node -v
```

Должна появиться строка вида `v22.14.0` или другая с числом **18 и выше**. Рядом можно проверить установщик пакетов:

```powershell
npm -v
```

Тоже должна появиться цифра, например `10.9.2`. Если вместо этого написано, что `node` не является командой — перезагрузите компьютер и повторите проверку. Если не помогло, установите Node.js ещё раз и не снимайте галочку PATH.

---

## 2. Открыть папку проекта в PowerShell

Так окно сразу окажется в нужной папке:

1. Откройте папку проекта в Проводнике (там, где виден файл `start.js`).
2. Щёлкните по **адресной строке** вверху окна (где написан путь к папке). Весь путь выделится.
3. Сотрите путь, напишите `powershell` и нажмите Enter.

Откроется синее или чёрное окно. В начале строки будет путь к вашей папке.

Другой способ, если адресная строка неудобна:

1. Откройте PowerShell любым способом.
2. Перейдите в папку. Кавычки обязательны, если в пути есть пробелы. Пример:

```powershell
cd "C:\путь\к\папке\bitrix24-deal-checker"
```

Подставьте свой путь. Узнать его можно в Проводнике: щёлкните адресную строку и скопируйте путь.

## 3. Первый запуск

В том же окне PowerShell введите:

```powershell
node start.js
```

и нажмите Enter.

**Первый раз** скрипт сам скачает зависимости и браузер. Это может занять несколько минут. Окно не закрывайте. Вы увидите примерно такое:

```text
Проверка сделок Битрикс24
Система: Windows_NT ...
Ставлю зависимости (первый раз, подождите)...
Ставлю браузер Chromium (первый раз, подождите)...
Запуск...
```

Строки про установку бывают только в первый раз. Со второго запуска их уже нет: ничего заново не качается.

Дальше скрипт спросит ссылку:

```text
Вставьте ссылку на отчёт и нажмите Enter:
>
```

---

## 4. Откуда взять ссылку на отчёт

Нужна ссылка на **отчёт со списком сделок**, не на одну сделку и не на главную Битрикса.

1. В своём обычном браузере откройте портал Битрикс24 и нужный отчёт CRM.
2. Дождитесь, пока на экране появится таблица со сделками.
3. Скопируйте адрес из адресной строки браузера целиком.

Адрес начинается с `https://` и внутри него есть `/crm/reports/report/`. Пример:

```text
https://ваш-портал.bitrix24.ru/crm/reports/report/view/123/
```

4. Вернитесь в окно PowerShell, **щёлкните по нему правой кнопкой мыши** — вставленный текст появится у знака `>`.
5. Нажмите Enter.

Если ссылка без `http://` или `https://`, скрипт напишет: `Нужна полная ссылка` — и остановится. Запустите `node start.js` снова и вставьте адрес целиком.

## 5. Вход в Битрикс и сама проверка

После ссылки скрипт напишет:

```text
Открываю браузер. Залогиньтесь и дождитесь отчёта (или нажмите Enter).
```

и откроет **отдельное** окно Chrome. Это окно скрипта. В нём:

1. Если Битрикс просит логин и пароль — войдите как обычно. Код из SMS или приложение тоже вводите сами. Скрипт пароль не видит и никуда его не сохраняет, кроме вашего входа в этом окне Chrome.
2. Дождитесь таблицы отчёта. Если открылась другая страница, перейдите на отчёт вручную в этом же окне.
3. Когда таблица со сделками видна, можно ничего не нажимать: скрипт дождётся сам (до 2 минут). Чтобы начать сразу, вернитесь в PowerShell и нажмите Enter.

Дальше окно Chrome лучше не трогать: скрипт сам открывает сделки по очереди. Вашим обычным Chrome в это время пользоваться можно.

В PowerShell по каждой сделке будет строка:

```text
[1/40] #4996 Ю26-0247 — OK
[2/40] #4994 Ю26-0229 — не сходится сумма в счёте поставщику и в списке затрат
  Не сходится сумма: в списке затрат есть суммы, которых нет в счетах и задачах: 580. Счета и задачи: [9500.14, 18130, 93000], список затрат: [580, 9500.14, 18130, 93000]
```

Короткий комментарий — сразу в строке сделки. Ниже, с отступом, подробно: какие суммы или поля не сошлись. Если замечаний несколько, комментарии пишутся через точку с запятой, а подробности нумеруются.

Пока идёт проверка:

- не закрывайте окно Chrome, которое открыл скрипт;
- не закрывайте окно PowerShell;
- второй раз `node start.js` не запускайте, пока первое окно Chrome ещё открыто.

Остановить проверку можно двумя способами: закрыть окно Chrome скрипта или в окне PowerShell нажать Ctrl+C. Уже проверенные сделки к этому моменту записаны в таблицу.

В конце появится итог:

```text
—— Итог ——
Всего: 40 | OK: 36 | Исправить: 4

Excel-отчёт: C:\...\results\check_latest.xlsx
Лист «Нужно исправить» — что поправить в сделках.

Готово. Enter — закрыть браузер...
```

Excel обычно открывается сам. Нажмите Enter — окно Chrome закроется. Пока Enter не нажат, браузер остаётся открытым, и можно глазами посмотреть последнюю сделку.

## 6. Как читать результат

Файл лежит в папке проекта:

`results\check_latest.xlsx`

В книге три листа:

| Лист | Что внутри |
| --- | --- |
| **Нужно исправить** | Только сделки с замечаниями, одна строка = одна сделка |
| **Все сделки** | Полный список проверенных сделок |
| **Итог** | Сколько всего / OK / исправить |

На листе «Нужно исправить»:

| Колонка | Что означает |
| --- | --- |
| ID | Номер сделки в Битриксе |
| Название | Название сделки |
| Ссылка | Можно вставить в браузер и открыть сделку |
| Комментарий | Коротко, что не так: «нет счёта заказчику», «не сходится сумма в счёте поставщику и в списке затрат». Несколько замечаний — через точку с запятой |
| Месяц завершения | Как скрипт прочитал поле |
| Счёт заказчику | `да`, `нет` или `не требуется` (для НАЛ и QR) |
| Суммы из задач / Суммы в графах | Для сверки |
| Подробно | Последний столбец: какие именно суммы, файлы или поля не сошлись |

После каждого полного прогона рядом появляется копия с датой, например `results\check_2026-11-10_21-24-58.xlsx`. Файл `check_latest.xlsx` — всегда последний прогон. Рядом по-прежнему пишется и CSV на всякий случай.

## 7. Следующие запуски

Логин запоминается в папке `.browser-profile` внутри проекта. Со второго раза окно Chrome часто открывается уже вошедшим в Битрикс.

Каждая новая проверка:

1. Дважды кликните `Проверка сделок.exe` (или в PowerShell: `node start.js`).
2. Вставьте **свежую** ссылку на отчёт. Ссылка с прошлого раза не сохраняется.
3. Дождитесь таблицы или нажмите Enter.
4. В конце откроется `results\check_latest.xlsx`.

Повторно ставить Node.js и зависимости не нужно.

## 8. Что именно проверяется

По каждой сделке из отчёта:

1. **Месяц завершения сделки** — поле должно быть заполнено (блок «О сделке»).
2. **Счёт заказчику** — в ленте есть комментарий с текстом «счёт заказчику» и вложенный файл. В имени файла должен быть номер сделки. Для сделок, название которых начинается с `НАЛ` или `QR`, счёт заказчику не требуется.
3. **Суммы.** Скрипт собирает суммы из:
   - задач «предоплата» и «постоплата» — из файлов счетов (Excel, PDF, Word);
   - задач «списание со склада» — из текста «сумма …», «всего …» или «итого …» (берётся итог, не цена одной позиции);
   - комментариев про СДЭК;
   - комментария «3% за эквайринг» у сделок НАЛ и QR — 3% от суммы сделки.
4. Эти суммы сверяются с графами затрат в блоке «Товары и маржинальность»: Поставщик, закупки, дополнительные расходы, расходы без НДС, транспорт, доп. расходы. **Порядок сумм не важен.** Если набор сумм совпал или сошёлся итог — сделка `OK`. Если в графах есть лишняя сумма или не хватает суммы из задачи — в отчёте будет, что исправить.

Названия полей и подсказки по задачам лежат в `config.js`. Их меняют, только если на портале поля называются иначе.

## 9. Если на Windows проверка идёт медленно

Так бывает из‑за антивируса: скрипт скачивает файлы счетов во временную папку, и Защитник Windows проверяет каждый файл.

**Ускорить, не отключая проверку счетов**

1. Откройте **Безопасность Windows** → **Защита от вирусов и угроз** → **Управление настройками** → **Исключения** → **Добавить исключение** → **Папка**.
2. Добавьте папку проекта целиком.
3. Отдельно добавьте папку `.browser-profile` внутри неё (она появляется после первого запуска).

**Ускорить сильнее, если суммы из файлов счетов не нужны**

1. Закройте скрипт.
2. Откройте файл `config.js` Блокнотом (правый щелчок по файлу → Открыть с помощью → Блокнот).
3. Найдите строку:

```js
downloadSupplierInvoices: true,
```

4. Замените `true` на `false` и сохраните файл.
5. Запустите `node start.js` снова.

Проверка станет быстрее. Суммы из вложенных счетов поставщика при этом не читаются, сверка по этим файлам будет неполной. Списания, СДЭК, эквайринг и счёт заказчику по-прежнему проверяются.

Чтобы вернуть чтение счетов, поставьте обратно `true`.

## 10. Подробный лог, если сделка «не проверяется»

В обычном режиме в окне только итог по сделке. Чтобы увидеть шаги (какие поля прочитаны, какие файлы открыты), перед запуском выполните в PowerShell:

```powershell
$env:VERBOSE = "1"
node start.js
```

Эта настройка живёт, пока открыто это окно PowerShell. В новом окне её нужно задать снова.

Тот же эффект навсегда: в `config.js` замените `verbose: false` на `verbose: true`.

## Если что-то пошло не так

**`node` не является внутренней или внешней командой**  
Node.js не установлен или окно PowerShell было открыто до установки. Закройте окно, откройте новое. Если не помогло — шаг 1 ещё раз, затем перезагрузка.

**Долго висит на «Ставлю зависимости» или «Ставлю браузер»**  
Первый запуск качает несколько сотен мегабайт. Подождите. Если появилось `Не удалось установить пакеты` или `Не удалось установить браузер` — проверьте интернет и снова выполните `node start.js`. Уже скачанное повторно не качается.

**`Нужна полная ссылка (http:// или https://)`**  
Вставлена не ссылка, а кусок адреса или название отчёта. Скопируйте адрес из браузера целиком.

**`Не вижу таблицу отчёта`**  
В окне Chrome скрипта нет таблицы сделок: не выполнен вход, открыта другая страница или отчёт ещё грузится. Войдите, откройте отчёт со сделками и запустите `node start.js` снова.

**`В отчёте нет ссылок на сделки`**  
Таблица открылась, но в ней нет кликабельных сделок. Проверьте фильтр отчёта: в списке должны быть сделки со ссылками.

**`Браузер закрыт — останавливаюсь`**  
Окно Chrome закрыли во время работы. Это нормальная остановка. Часть сделок уже лежит в `results\check_latest.xlsx`.

**Chrome не открывается, в логе `Не удалось запустить`**  
Поставьте Google Chrome с https://www.google.com/chrome/ и запустите скрипт ещё раз. Если окно прошлого запуска ещё висит в панели задач — закройте его: два скрипта сразу делят одну папку профиля и мешают друг другу.
